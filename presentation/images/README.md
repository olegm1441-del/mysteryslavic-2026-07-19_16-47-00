## Как добавить оставшиеся кадры

Способ 1 — положить оригинал в `images/source/` под ожидаемым именем и запустить
подготовку:

```bash
python3 prepare_images.py && node build_deck.js
```

Ожидаемые имена исходников: `IMAGE_03_fieldwork_16x9.png`, `IMAGE_04_lifecycle_16x9.png`,
`IMAGE_05_dashboard_16x9.png`, `IMAGE_06_spare_repair_4x3.png`, `IMAGE_07_line_wide_16x9.png`.
Имя можно поменять — оно задаётся в таблице `PHOTOS` внутри `prepare_images.py`.

Способ 2 — положить готовый файл прямо в `images/` под итоговым именем:
`03-fieldwork`, `04-lifecycle`, `05-dashboard`, `06-spare-repair`, `07-line-wide`.
Расширение любое из `.jpg`, `.jpeg`, `.png` — генератор найдёт файл сам.

## Что делает prepare_images.py

- **Кроп под панель слайда там, где центр не подходит.** pptxgenjs умеет только
  центральный кроп. Для титульного кадра это неверно: шкаф и инженер стоят справа,
  центральный кроп срезал бы их. Поэтому IMAGE 01 режется заранее с якорем `right`.
- **Даунскейл** до 1600 px по длинной стороне и перевод в JPEG q88: исходные PNG весили
  по 2,5 МБ, готовые — 200–300 КБ. На качество в презентации это не влияет.
- **Иконки**: обрезка прозрачных полей (в исходниках глиф занимал около 60% холста),
  приведение к квадрату с полем 6%, даунскейл до 512 px, PNG с альфа-каналом.

Пропорции панелей в `prepare_images.py` должны совпадать с геометрией слайдов в
`build_deck.js`. Если менять раскладку слайда — поправить в обоих местах; иначе кадр
просто доедет центральным кропом при вставке, что для большинства слайдов нормально.
