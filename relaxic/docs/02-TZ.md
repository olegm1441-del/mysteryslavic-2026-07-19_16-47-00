# Relaxic — техническое задание на сайт

Версия 1.0. Это тот документ, по которому будет собираться сайт на шаге 2.
Связанные: `01-BRIEF.md` (зачем), `03-BRANDBOOK.md` (как выглядит), `06-SITEMAP.md` (структура).

---

## 1. Стек

| Слой | Решение | Почему |
|---|---|---|
| Фреймворк | **Next.js 16.3** (Turbopack), App Router, TypeScript 7 | SSR для SEO, один деплой на Railway, серверные экшены вместо отдельного API |
| Стили | **Tailwind CSS 4.3** + CSS-переменные из бренд-бука | Токены живут в одном месте, темы переключаются атрибутом |
| БД | **PostgreSQL** (Railway) | Просили Railway |
| ORM | **Prisma 7.10** + `@prisma/adapter-pg` | Миграции из коробки, типобезопасность |
| Состояние корзины | **Zustand** + `persist` в localStorage | Корзина переживает перезагрузку без авторизации |
| Анимация | **motion** (ex-framer-motion) | Декларативно, уважает `prefers-reduced-motion` |
| Плавный скролл | **Lenis** | Для «галерейных» страниц |
| Карусели | **Embla Carousel** | Лёгкая, доступная, тач-нативная |
| Валидация | **Zod 4** | Одна схема на клиент и сервер |
| Иконки | **Lucide React** | Единая обводка, tree-shaking |
| Шрифты | `next/font/google`: Unbounded + Onest | Самохостинг, без FOUT, subsets cyrillic |
| Уведомления | **Telegram Bot API** | Просили |

Отдельного бэкенда нет. Приём заказа — Server Action, не публичный роут:
у публичного POST-эндпоинта на заказ нет защиты от спама, а Server Action привязан к сессии формы.

**Версии зафиксированы по факту установки**, не по памяти: всё поставлено на шаге 1,
`npx next build` проходит. Точные версии — в `package-lock.json`.

> **Про готовый шаблон.** Не берём. Бренд-бук требует собственную типографику,
> тёмную тему с двумя поверхностями и фирменную анимацию «раскрашивание» —
> любой коммерческий шаблон пришлось бы переписать процентов на восемьдесят,
> и его наследие мешало бы больше, чем помогало. Вместо шаблона — точечные
> библиотеки: `motion` для анимации, `lenis` для скролла, `embla` для каруселей,
> `lucide` для иконок.

### Особенность Prisma 7
В седьмой версии строка подключения переехала из `schema.prisma` в `prisma.config.ts`,
а клиент требует драйвер-адаптер. Настроено:

- `prisma.config.ts` — `datasource.url` из `DATABASE_URL`, путь миграций, команда сида
- `lib/db.ts` — клиент на `PrismaPg`, синглтон через `globalThis`, чтобы hot reload
  в dev не плодил пулы соединений
- **`prisma` в `devDependencies` закреплён точной версией `7.10.0`.** Диапазон `^7.10.0`
  ломает установку багом npm (`Cannot read properties of null (reading 'edgesOut')`).

## 4. Карточка товара

Порядок блоков = порядок снятия возражений:

1. Хлебные крошки
2. Галерея: 4–6 изображений + зум, миниатюры слева на десктопе
3. Название (H1), вселенная и техника — ссылками
4. Рейтинг → якорь на отзывы
5. Цена, старая цена, экономия
6. **Сложность 1–5 точками · Время сборки в часах · Количество цветов**
7. Выбор размера — влияет на цену
8. «В корзину» — sticky на мобильном при скролле
9. **Срок и стоимость доставки** — здесь, а не в корзине
10. **«Что в коробке»** — список с фото компонентов
11. Спецификация: плотность холста, тип страз/красок, комплектация
12. Описание: **что это за кадр и почему он важен** — сторителлинг, а не ТТХ
13. Отзывы с фото
14. **Из этой вселенной** — 4 товара
15. **Похожие по сложности** — 4 товара
16. **Статья по теме** — 1 материал журнала

Пункты 14–16 обеспечивают три исходящие ссылки с каждой карточки.

## 5. Корзина и заказ

### Корзина
- Drawer справа при добавлении, отдельная страница `/cart` для полного просмотра
- Zustand + localStorage, переживает перезагрузку
- Полоса прогресса до бесплатной доставки: «Доберите на 610 ₽ — доставим бесплатно»
- «Часто покупают вместе»: рамка, подставка, лупа, доп. набор страз
- Светлая тема (`data-surface="light"`)

### Чекаут — один экран
Поля: имя, телефон, e-mail, способ доставки, адрес/пункт выдачи, комментарий.
**Без обязательной регистрации.**

Обязательный чекбокс, снят по умолчанию:
> Я согласен на обработку персональных данных и принимаю условия оферты

Ссылки на `/legal/privacy` и `/legal/offer` открываются в новой вкладке.
Факт согласия пишется в таблицу `Consent` с текстом версии, IP и временем — этого требует
152-ФЗ, и без записи согласие невозможно подтвердить при проверке.

### После оформления
1. Транзакция в БД: `Order` + `OrderItem[]`
2. Отправка в Telegram
3. Редирект на `/order/[number]` — номер, состав, сроки, что дальше
4. Корзина очищается

**Если Telegram недоступен — заказ всё равно сохраняется.** Ошибка нотификации пишется в
`Order.notifyError` и не роняет оформление. Терять заказ из-за недоступности мессенджера нельзя.

## 6. Telegram-интеграция

```
POST https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/sendMessage
{
  "chat_id": "<TELEGRAM_CHAT_ID>",
  "text": "<HTML>",
  "parse_mode": "HTML",
  "disable_web_page_preview": true
}
```

Формат сообщения:

```
🎨 Заказ №R-2609-0042

👤 Иван Петров
📱 +7 999 123-45-67
✉️ ivan@mail.ru

📦 Состав:
1. Хогвартс. Большой зал — алмазная мозаика, 40×50 — 2 490 ₽
2. Мини-набор «Сова» — картина по номерам, 20×20 — 690 ₽

🚚 СДЭК, ПВЗ Казань, ул. Баумана 1
💬 «Позвоните после 18:00»

💰 Итого: 3 180 ₽ (доставка бесплатно)
🕒 22.09.2026, 21:14
```

**Реализация.** Токен и chat_id — только в переменных окружения, в код не попадают.
Отправка обёрнута в `try/catch` с таймаутом 5 с и одним повтором.
Если `TELEGRAM_BOT_TOKEN` не задан — в консоль пишется предупреждение, сайт работает.

> Вы написали, что безопасность бота не важна. Учтено: отдельной защиты не делаем.
> Но в переменных окружения токен лежит по той же причине, по которой он не лежит в коде —
> так его можно поменять на Railway за десять секунд, не пересобирая проект.
> Это удобство, а не осторожность.

Чтобы получить `chat_id` группы: добавить бота в чат, написать любое сообщение,
открыть `https://api.telegram.org/bot<TOKEN>/getUpdates`, взять `message.chat.id`
(у групп он отрицательный).

## 7. Cookie-баннер и персональные данные

### Требования, которые нельзя обойти
С сентября 2025 простого уведомления «мы используем cookie» недостаточно.
Пользователь должен иметь возможность **отказаться** от аналитических и рекламных трекеров,
и скрипты аналитики грузятся **только после согласия**. Обработка ПД без согласия —
штраф от 300 000 до 700 000 ₽ для юрлица.

### Что делаем
Панель внизу экрана, **не модальная, сайт остаётся рабочим**:

```
Мы используем cookie, чтобы сайт помнил корзину и мы понимали,
что вам интересно. Подробнее в Политике.

[Только необходимые]  [Настроить]  [Принять все]
```

- Три кнопки равнозначны визуально. «Принять все» не подсвечен ярче — тёмный паттерн,
  и по нынешним требованиям это повод для претензии.
- «Настроить» → переключатели по категориям: **необходимые** (всегда вкл, отключить нельзя),
  **аналитические**, **маркетинговые**.
- Выбор — в `localStorage` **и** в таблицу `Consent` с версией текста и временем.
- **Яндекс.Метрика и любые пиксели подключаются только после согласия на аналитику.**
- Панель появляется через 1,2 с с задержкой, снизу, анимацией вверх. Не перекрывает контент —
  контейнер получает нижний отступ.
- Повторно не показывается 6 месяцев. Изменить выбор — ссылка в подвале.

### Локализация данных
152-ФЗ требует, чтобы база с ПД граждан РФ физически находилась в России.
**Railway — вне РФ.** Это зафиксировано как риск в `00-QUESTIONS.md` (вопрос 8).
Архитектурно переезд = замена `DATABASE_URL`, код не меняется.

## 9. Адаптивность

Проверяется на реальных размерах, а не «на глаз»:

| Ширина | Устройство | Что проверяем |
|---|---|---|
| **320** | iPhone SE 1 | Ничего не переполняется, нет горизонтального скролла |
| 360 | Android базовый | Каталог в 1 колонку |
| 390 | iPhone 14/15 | Sticky-кнопка не перекрывает контент |
| 430 | iPhone Pro Max | |
| 768 | iPad портрет | Каталог в 2 колонки |
| 1024 | iPad альбом | 3 колонки, боковые фильтры |
| 1280 | Ноутбук | 4 колонки |
| 1440 / 1920 | Десктоп | Контейнер 1280, поля растут |
| 2560 | 4K | Текст не растягивается на всю ширину |

**Обязательно:**
- Область нажатия ≥ 44×44 px
- Текст ≥ 16 px в полях ввода — иначе iOS зумит форму при фокусе
- `dvh` вместо `vh` — иначе адресная строка мобильного браузера ломает высоту
- Safe area для iPhone с вырезом: `env(safe-area-inset-bottom)` для sticky-панели
- Ландшафтная ориентация на телефоне не ломает hero
- Проверка при 200% зуме браузера

## 10. Производительность и SEO

**Цели:** LCP < 2,5 с · CLS < 0,1 · INP < 200 мс · Lighthouse ≥ 90 на мобильном.

- `next/image` везде, AVIF + WebP, явные `width`/`height` против сдвигов
- Шрифты через `next/font` с `display: swap`, подмножество только нужных subsets
- Серверные компоненты по умолчанию, `"use client"` только где нужна интерактивность
- Анимации только на `transform` и `opacity`

**SEO:**
- Уникальные `title` и `description` на каждой странице, шаблоны в `generateMetadata`
- Open Graph и Twitter Card на всех публичных страницах
- JSON-LD: `Product` + `Offer` + `AggregateRating` на карточке, `Article` в журнале,
  `BreadcrumbList` везде, `Organization` на главной
- `sitemap.xml` и `robots.txt` генерируются
- Канонические URL, фасеты каталога — `noindex, follow`
- ЧПУ на латинице транслитом
- `hreflang` не нужен — сайт одноязычный

## 11. Доступность

- Семантические теги, один `<h1>` на страницу, иерархия заголовков без пропусков
- Все интерактивные элементы достижимы с клавиатуры, видимый `:focus-visible`
- `alt` у всех изображений; декоративные — `alt=""`
- Формы: `<label>` связаны, ошибки через `aria-describedby` и текстом, не только цветом
- Модалки и drawer: ловушка фокуса, Esc, возврат фокуса
- `prefers-reduced-motion` отключает всю анимацию
- Контраст — по таблице из бренд-бука, проверено расчётом

## 13. Запуск одной командой

```bash
npm run pzm
```

Делает: установку зависимостей → генерацию Prisma Client → применение схемы к БД →
наполнение демо-данными → запуск dev-сервера на `http://localhost:3000`.

Если `DATABASE_URL` не задан, сайт всё равно поднимается — на демо-данных из фикстур.
Посмотреть проект можно вообще без настройки базы.

**Проверено:** `npm run pzm` поднимает сервер примерно за 20 секунд,
`/` и `/api/health` отвечают 200.
